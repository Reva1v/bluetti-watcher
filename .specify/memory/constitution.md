# Bluetti Watcher (Rust) Constitution

## Core Principles

### I. Станция — чтение и белый список записей (NON-NEGOTIABLE)

- Программа меняет на станции только настройки из белого списка, и только по явному действию
  владельца на дашборде. Белый список: режим зарядки (регистр 2020, значения 0 — стандартный,
  1 — тихий, 2 — турбо). Сервис сам, без нажатия, в станцию не пишет.
- Запись регистра Modbus (функция 0x06) собирается одной функцией, которая принимает только значения
  из белого списка; произвольного адреса или значения она не принимает. Расширение списка — изменение
  конституции.
- Кроме этих записей в станцию уходят только команды чтения (0x03) и сообщения шифрованного
  рукопожатия. Служебные записи BLE-дескрипторов (включение уведомлений, CCCD) допустимы.
- Тест проверяет, что все исходящие кадры — это чтение, рукопожатие или запись из белого списка.

Обоснование: ошибочная запись может выключить выход AC и обесточить ПК, ради защиты которого
программа существует. Режим зарядки на питание ПК не влияет, поэтому он разрешён, а всё остальное нет.

### II. Безопасность ПК важнее реакции

- Гибернация и смена режима питания происходят только по подтверждённым показаниям: несколько
  согласных показаний подряд и свежее показание прямо перед гибернацией.
- Неполное, неправдоподобное или пропущенное показание никогда не запускает действие.
- Есть аварийный выключатель (файл `no-hibernate` в каталоге данных) и режим `--dry-run`, в котором
  все действия только пишутся в лог.
- Любое изменение плана питания обратимо: прежнее состояние сохраняется и возвращается при
  восстановлении сети.

### III. Невидимый фон

- Сервис работает без окна, без консоли и без значка в трее, стартует при входе пользователя без
  прав администратора.
- Интерфейс — дашборд на `127.0.0.1`, открывается ярлыком. Закрытие окна дашборда не
  останавливает сервис.
- HTTP слушает только loopback; запросы с чужим `Host` отклоняются, изменяющие запросы требуют
  заголовка, который другие сайты отправить не могут.

### IV. Один бинарник без рантаймов

- Поставка — один `.exe` на Rust (stable, Windows 10/11 x64). Python, .NET, Node и прочие рантаймы
  MUST NOT требоваться. Дашборд встроен в бинарник.
- Внешние процессы допускаются только для системных утилит Windows (`powercfg`, `shutdown`,
  `nvidia-smi`), когда нет надёжного API.

### V. Тестируемое ядро

- Логика решений (сеть пропала/вернулась, уровни батареи, гибернация, оценка времени) — чистый код
  без I/O и без системных часов; время передаётся параметром.
- Bluetooth, файлы, процессы и часы скрыты за трейтами и подменяются в тестах.
- Протокол BLUETTI (кадры Modbus, CRC, шифрование) покрыт тестами на записанных байтах.
- Новая логика решений сопровождается тестами в том же изменении.

### VI. Простота

- Делаем только то, что нужно владельцу: одна станция (AC180P), один ПК. Облачный источник BLUETTI в проект
  не входит.
- График ДТЭК — только показ: решения (eco, уровни, гибернация) его не читают. Единственный внешний запрос
  программы — чтение публичного набора данных с GitHub (HTTPS, только GET); адрес владельца никуда не уходит.
- Новая зависимость или настройка должна решать реальную задачу; конфиг имеет рабочие значения по
  умолчанию, кроме адреса станции.

## Технические ограничения

- Язык: Rust stable, edition 2024. Асинхронность: `tokio`.
- Bluetooth LE: WinRT через `windows` crate или `btleplug`; выбор фиксируется в плане первой фичи.
- Хранилище: SQLite (`rusqlite`, bundled). HTTP: лёгкий сервер (`axum` или аналог).
- Данные, конфиг и лог: `%LOCALAPPDATA%\bluetti-watcher`.
- Время в хранилище — UTC; на дашборде — локальное время ПК.

## Процесс разработки

- Фичи ведутся по Spec Kit: spec → clarify → plan → tasks → analyze → implement; спеки в
  `specs/<NNN-name>/`. Баги — через `/speckit-bug-*`. Мелкие правки в один файл — без флоу.
- Перед коммитом: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
- Сообщения коммитов — на английском.
- Поведение, которое нельзя проверить без живой станции, проверяет владелец; результат такой
  проверки фиксируется в спеке фичи.

## Governance

- Конституция стоит выше прочих практик проекта. Каждый план (`/speckit-plan`) проходит проверку
  на соответствие принципам; отступление записывается в раздел Complexity Tracking с обоснованием.
- Изменение конституции — отдельный коммит с обновлением версии: MAJOR — удаление или
  переопределение принципа, MINOR — новый принцип или раздел, PATCH — уточнения формулировок.
