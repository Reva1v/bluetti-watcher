# Plan: 005 — Сильный и Максимальный Eco с затемнением мониторов

Формат короткий, как у 002 и 004: исследование, модель данных и контракты собраны здесь.

## Решения

- **Уровни** `model.rs`: `EcoLevel { None, Eco, Strong, Deep }` с `PartialOrd, Ord` (порядок объявления — сила уровня).
  `Deep` остаётся в коде и JSON (`"deep"`), на экране называется «Максимальный Eco»; `Strong` — `"strong"`.
- **Чистое ядро** `src/decision/boost.rs` (без I/O и часов), состояние — поле `DecisionState.boost`:
  - `Boost { strong: Switch, max: Switch, dim_off: bool }`, `Switch { on: bool, auto: bool }` (`auto` — включён порогом).
  - `BoostRequest { Strong(bool), Max(bool), Dim(bool) }`; `Input.boost_requests: Vec<BoostRequest>` (нажатия с прошлого цикла,
    по порядку).
  - `request(s, req, out)`: ставит `on`, `auto = false`; `Dim(v)` → `dim_off = !v`. Событие `boost-manual` с текстом
    («Сильный Eco включён вручную», «Затемнение мониторов выключено»).
  - `on_threshold(s, which, soc, out)`: вызывается из лестницы уровней; при `manual == Max` ничего не включает (FR-006),
    иначе `Switch { on: true, auto: true }`.
  - `on_mains_back(s, out)`: в `mains::update` там же, где закрывается отключение: оба `Switch` выключаются (FR-007).
  - `level(s) -> EcoLevel`: `Deep`, если `max.on`; `Strong`, если `strong.on`; иначе `None`.
  - `settle(s)`: оба выключены → `dim_off = false` (FR-010). Вызывается в `decide` перед синхронизацией.
  - `dim_wanted(s, game: bool) -> Dim`: `Dim { None, Secondary, All }` — `None`, если уровень ниже `Strong` или `dim_off`;
    `Secondary` (все, кроме основного), если запущена игра; иначе `All`. `Input.game_running: bool` приходит от сервиса.
- **Желаемый уровень** `mains::desired`: `max(base, boost::level(s))`, где `base` — прежняя таблица без `deep`
  (`Max → None`, `Eco → Eco`, `Auto` в отключении → `Eco`, иначе `None`). Поле `Outage.deep` удаляется: старое состояние
  читается (лишний ключ JSON игнорируется), максимальный уровень в таком отключении включится вручную или в следующем.
- **Пороги** `decision/levels.rs`: новый `Level::Strong` первым в перечислении (`Strong < Low < Critical < Warn < Hibernate`,
  сравнения `l < Level::Warn` остаются верны). `threshold(Strong) = cfg.levels.strong`, `effective_threshold(Strong) =
  cfg.levels.strong.max(warn)`. Лестница: `[Strong, Low, Critical, Warn]`, по одной ступени за цикл. `reach(Strong)` —
  событие `level-strong` и `boost::on_threshold(Strong)`; `reach(Low)` — как сейчас, но вместо `o.deep = true` —
  `boost::on_threshold(Max)`. У `Strong` нет уведомления Windows (`notify_kind → None`). Один раз за отключение —
  через существующий `levels_reached`.
- **Затемнение в ядре**: `DecisionState { dim: Dim, dim_applied: Dim }`, `Action::SetDim(Dim)`, ключ бэкоффа `dim`;
  `boost::sync_dim` по образцу `mains::sync_eco`, `report` учитывает результат. `guards::reset` состояние `boost` и `dim`
  не сбрасывает (как ручной eco и отключение).
- **Яркость** `src/power/brightness.rs`:
  - трейт `Brightness { fn monitors(&mut self) -> Result<Vec<Monitor>, String>; fn set(&mut self, id: &str, value: u32) -> Result<(), String>; }`,
    `Monitor { id: String, primary: bool, min: u32, cur: u32, max: u32 }` (`primary` — `MONITORINFOF_PRIMARY`). В список
    попадают только мониторы, отдавшие яркость.
  - `DimRestore { monitors: BTreeMap<String, u32> }` в `meta.dim_restore`; сервис сохраняет его до записи, как `power_restore`.
  - `apply(b, target: Dim, saved, pct, dry) -> (Option<DimRestore>, Vec<PartResult>)` — одна функция на все переходы.
    Монитор должен быть затемнён, если `All`, или `Secondary` и он не основной. Такой монитор без сохранённого значения:
    запомнить `cur` (имеющееся не перезаписывается: сценарий 3.6 и потеря состояния) и записать
    `min + (max − min) × pct / 100`; с сохранённым значением повторной записи нет. Монитор, который затемнён быть не
    должен, но имеет сохранённое значение: вернуть его и убрать из сохранённых. Сохранённый монитор, которого больше
    нет, убирается с пометкой. Остаток после отказа повторяется по бэкоффу.
  - `SetDim` успешен, если ни одна запись не отказала; монитор без поддержки — не отказ.
  - `WindowsBrightness`: `EnumDisplayMonitors` → `GetPhysicalMonitorsFromHMONITOR` → `GetMonitorBrightness` /
    `SetMonitorBrightness` → `DestroyPhysicalMonitors`. `id` = имя дисплея из `GetMonitorInfoW` + `#` + номер физического
    монитора (`\\.\DISPLAY1#0`). Новая feature `windows`: `Win32_Devices_Display`. Новых зависимостей нет.
- **Игры** `src/power/games.rs`: трейт `Games { fn running(&mut self) -> bool }`. `WindowsGames`: `[eco] dim_skip_games =
  false` → `false`; иначе `HKCU\Software\Valve\Steam\RunningAppID != 0` или запущен процесс с именем из
  `[eco] game_processes` (сравнение без регистра, через ToolHelp, уже подключён). Ошибка чтения — `false`. Выбор по
  имени — чистая функция `matches(names, list)`.
- **Питание** `power/`: `Strong` идёт по ветке `Eco | Deep`; процессор — `strong_cpu_max_pct`; `gpu::level_word` /
  `parse_level` — слово `strong`, `limit_for(Strong)` = `max(min, default × strong_gpu_pct %)`; `services::plan` — как для eco.
- **Сервис** `service.rs`:
  - канал `Channels.boosts`; нажатие будит цикл так же, как выбор режима; все накопленные нажатия уходят в `Input`.
  - `Action::SetDim(target)` → `set_dim`: `[eco] dim = false` — успех без действий; иначе `brightness::apply`, события
    `dim-on` / `dim-off` с причиной (в том числе «запущена игра: основной монитор не затемнён»), отказ части —
    `eco-part-failed`.
  - перед каждым `decide` сервис спрашивает `Games::running()`: иначе в цикле, где уровень включается, основной
    монитор успел бы погаснуть. Снимок процессов делается, только если `game_processes` не пуст.
  - `start`: есть `dim_restore`, а затемнение не нужно — вернуть яркость (как с `power_restore`).
  - события уровня: `eco-strong` «Сильный Eco включён», `eco-deep` «Максимальный Eco включён».
- **HTTP**: `POST /api/boost` и поле `boost` в `/api/now`, контракт ниже. Защита та же, что у `/api/mode`.
- **Дашборд** (`index.html`, `app.js`, `style.css`): под сегментом Авто / Eco / Максимум — две отдельные кнопки-переключателя
  «Сильный Eco» и «Максимальный Eco» (`aria-pressed`, пометка «авто»), ниже флажок «Гасить мониторы». Это не второй
  сегмент: кнопки независимы и могут быть включены обе. Текст карточки и строка статуса знают `strong`; «глубокий eco»
  везде заменён на «Максимальный Eco» (также `notify.rs`, `install.rs`).

## Исследование

- Проверено вживую 2026-11-10 из сессии владельца: оба монитора («Generic PnP Monitor») отдали `min=0 cur=100 max=100`,
  приняли 0 и 100, повторное чтение подтвердило значение. Запись и чтение занимают доли секунды на монитор.
- Сервис работает в сессии пользователя (принцип III), поэтому мониторы ему доступны.
- Описания мониторов одинаковые, дескрипторы физических мониторов не постоянны — ключом служит имя дисплея и номер.
  При смене раскладки дисплеев сохранённое значение может не найти монитор: оно отбрасывается с событием.
- Steam держит `RunningAppID` в `HKCU\Software\Valve\Steam` (проверено 2026-11-10: без игры значение 0, при
  запущенном Deadlock — 1422450). Отвергнуто: поиск процессов по пути
  `steamapps\common` (нужен путь каждого процесса и список библиотек), определение полноэкранного окна (ловит видео и
  браузер).
- Отвергнуто: WMI `WmiMonitorBrightness` (только встроенные панели, у владельца их нет; принцип VI), гамма и оверлей
  (это программное затемнение, FR-009), отдельный крейт `brightness`/`ddc-hi` (хватает четырёх вызовов Win32, принцип VI).

## Контракт: `config.toml`

```toml
[levels]
strong = 50            # заряд в отключении: «Сильный Eco»; должен быть выше low

[eco]
strong_cpu_max_pct = 65
strong_gpu_pct = 50
dim = true             # гасить мониторы на сильном и максимальном уровне
dim_pct = 0            # яркость при затемнении, 0–100
dim_skip_games = true  # запущена игра: основной монитор не гасить
game_processes = []    # имена exe игр не из Steam, например ["eldenring.exe"]
```

`strong ≤ low` — все уровни по умолчанию и предупреждение (существующая проверка порядка).

## Контракт: HTTP

- `POST /api/boost`, заголовок как у `/api/mode`; тело — ровно один ключ: `{"strong": bool}`, `{"max": bool}` или
  `{"dim": bool}`. Ответ `202` с тем же телом; иначе `400`; без заголовка `403`.
- `/api/now` и поток: `"boost": { "strong": { "on": bool, "auto": bool }, "max": { "on": bool, "auto": bool }, "dim": bool }`
  (`dim` — состояние переключателя «Гасить мониторы»), `"dimmed": "none" | "secondary" | "all"` (что затемнено сейчас),
  `"eco"` получает значение `"strong"`.

## Конституция

- I: в станцию ничего нового не пишется.
- II: уровни включаются только по принятым согласным показаниям в подтверждённом отключении; яркость сохраняется до
  изменения и возвращается; `--dry-run` только пишет в лог.
- III: окон и значков нет; новый изменяющий запрос под той же защитой.
- IV: один `.exe`, новых зависимостей и внешних процессов нет.
- V: решения в `decision/boost.rs`, яркость за трейтом `Brightness`.
- VI: настройки с рабочими значениями по умолчанию; встроенные панели не поддерживаются.
- Отступлений нет.

## Тесты

- `decision/boost` и `mains::desired`: таблица уровня для всех сочетаний выбора и переключателей (включая «Максимум» +
  переключатель, оба переключателя, выключение одного); ручное включение переживает начало отключения и снимается
  возвратом сети; ручное при сети без отключения держится; выключенный владельцем авто-уровень не включается снова;
  `dim_off` возвращается после снятия обоих и держится, пока один активен; состояние через JSON; старое состояние с
  `deep` читается.
- `decision/levels` и `tests/scenarios.rs`: границы 51/50 и 21/20; отключение с 40 % включает сильный сразу после
  подтверждения; 60 → 15 % даёт ровно одно включение каждого уровня; при сети пороги молчат; «Максимум» блокирует
  автоматику, ручное включение работает; отвергнутое показание ничего не включает; одна ступень за цикл.
- `power/brightness` с поддельным `Brightness`: 100 и 70 → 0 → 100 и 70; повторное затемнение не перезаписывает
  сохранённое; сохранённый 0 остаётся 0; отказ записи одного монитора не мешает другому и оставляет остаток; пропавший
  монитор отбрасывается; `dim_pct` и ненулевой `min`; `--dry-run` не пишет.
- `power/brightness`, игра: `Secondary` гасит только не основной; `All → Secondary` возвращает основной и не трогает
  второй; `Secondary → All` гасит основной; `Secondary → None` возвращает второй; единственный монитор при `Secondary` не
  гаснет.
- `decision/boost::dim_wanted`: таблица уровень × `dim_off` × игра; смена игры между циклами даёт `SetDim` один раз.
- `power/games::matches`: регистр, пустой список, расширение `.exe`.
- `power`: процессор и GPU для `Strong`, слова запроса GPU туда и обратно.
- `service`: уровень включается при запущенной игре — основной не гаснет ни на цикл; `dim_skip_games = false` гасит все. `SetDim` сохраняет `dim_restore` до записи и удаляет после возврата; `dim = false` ничего не трогает;
  возврат яркости на старте; отказ и повтор по бэкоффу; события.
- `http`: `/api/boost` — заголовок, одно поле, неверные тела; поле `boost` в `/api/now`.
- `config`: новые ключи, границы, порядок `strong > low`.
- Тесты без окон и без настоящих мониторов (CLAUDE.md): `WindowsBrightness` в тестах не вызывается.
