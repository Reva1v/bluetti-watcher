# 003 — Режим зарядки станции с дашборда

Владелец меняет режим зарядки AC180P (стандартный / тихий / турбо) с дашборда, а не из приложения BLUETTI.
Основание — конституция 2.0.0, принцип I (белый список записей).

## Требования

- FR-001: Сервис при каждом чтении читает регистры 2020×2. Значения: 0 — стандартный, 1 — тихий, 2 — турбо;
  остальные значения (4 — «свой») показываются как «неизвестно». Если станция не ответила на этот блок,
  показание всё равно принимается.
- FR-002: В карточке «Заряд», рядом с «Сеть есть», — чип с текущим режимом; по клику меню из трёх режимов с
  подсказками. Отмечен режим, прочитанный со станции. Чипа нет, пока режим не прочитан.
- FR-003: Нажатие → `POST /api/charging` → сервис сразу пишет регистр 2020 (Modbus 0x06), ждёт эхо станции,
  затем делает обычный цикл чтения. В ответе — итог и режим по этому чтению. Из нескольких нажатий подряд
  пишется последнее.
- FR-004: Кадр записи собирает только `ac180p::charging_mode_request(ChargingMode)`. Других записей нет, тест
  протокола проверяет все исходящие кадры.
- FR-005: Без включённых правил (`specs/004-charging-auto`) сервис сам режим зарядки не меняет. В `--dry-run` запись не выполняется.
- FR-006: Успех → событие `charging-mode`, ошибка → `action-failed` и текст внизу карточки «Заряд».

## План

- `ble/modbus.rs`: `write_request` (`pub(super)`), `FN_WRITE`, разбор эха и исключения 0x86, длины кадров 0x06/0x86.
- `ble/ac180p.rs`: `ChargingMode`, `SETTINGS = (2020, 2)`, `charging_mode_request`, `is_allowed_write`.
- `ble/mod.rs`: общее подключение и рукопожатие (`open`), `read_block`, необязательный блок настроек,
  `write_charging_mode`.
- `service.rs`: `StationReader::write_charging_mode`, канал `charging`, запись до чтения в `cycle`,
  `NowView.chargingMode`.
- `http`: `POST /api/charging` (заголовок, как у `/api/check`, ожидание до 2 мин), контракт в
  `001/contracts/http-api.md`.

## Тесты

- modbus: кадр записи, CRC, эхо, исключение 0x86, длины кадров.
- ac180p: чтение режима, белый список отвергает чужой адрес, значение 4 и кадр чтения.
- protocol: запись с шифрованием и без, отказ станции → `modbus-error`, молчание на блоке 2020 не мешает
  показанию, все исходящие кадры — из белого списка.
- service: запись, затем чтение, побеждает последнее нажатие; ошибка записи и `--dry-run` станцию не меняют.
- http: заголовок, проверка тела, форма ответа, `chargingMode` в `/api/now`.

## Проверка владельцем (живая станция)

- [ ] Дашборд показывает тот же режим, что приложение BLUETTI.
- [ ] Переключение с дашборда меняет режим в приложении BLUETTI (все три значения).
