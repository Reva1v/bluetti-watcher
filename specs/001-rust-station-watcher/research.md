# Research: 001-rust-station-watcher

Источник протокола — `bluetti-bt-lib` 0.1.8 (`bluetooth/encryption.py`, `bluetooth/device_reader.py`,
`devices/ac180p.py`), сам основан на `nhurman/bluetti_mqtt`. Проверки на ПК владельца сделаны 2026-10-14.

## R1. Протокол AC180P

- **Decision**: свой модуль протокола на Rust: Modbus RTU поверх BLE GATT + шифрование IoT v2.
- **Факты**:
  - Сервис BLE: notify `0000ff01-0000-1000-8000-00805f9b34fb`, write `0000ff02-0000-1000-8000-00805f9b34fb`.
  - Запрос чтения: `01 03 <addr u16 BE> <count u16 BE> <crc16 modbus LE>`. Ответ: `01 03 <len> <data…> <crc LE>`,
    значения u16 BE. Ошибка Modbus: второй байт `0x83`.
  - Регистры AC180P: 102 SOC % (0–100), 140 выход DC Вт, 142 выход AC Вт, 144 вход DC Вт, 146 вход AC Вт,
    1314 напряжение входа AC ÷10 В. Читаем блоками: `100×10`, `140×10`, `1314×1` (протокол v2 принимает блоки по 10,
    так делает `bluetti-readall`). Поля режима выхода (`AC_OUTPUT_MODE`) у AC180P нет — сеть определяется по входу AC.
  - Шифрование (после подписки на notify станция сама шлёт challenge):
    1. `2A2A 01 xx <4 байта>` + checksum (сумма байт тела, u16 BE). IV₀ = MD5(reverse(4 байта)),
       K₀ = IV₀ XOR `459FC535808941F17091E0993EE3E93D`. Ответ: `2A2A 0204 IV₀[8..12]` + checksum, открытым текстом.
    2. Станция: `2A2A 03…` (challenge accepted).
    3. Станция шлёт зашифрованное K₀/IV₀ (AES-128-CBC, заголовок `len u16 BE`, затем блоки) сообщение
       `2A2A 04 xx <pubkey 64> <sig 64>`; подпись ECDSA-P256-SHA256 над `pubkey ‖ IV₀`, проверяется ключом K2
       (константа в коде). Мы генерируем пару P-256, подписываем `my_pub ‖ IV₀` ключом L1 (константа), шлём
       `2A2A 0580 <my_pub 64> <sig raw r‖s 64>` + checksum, зашифровав K₀/IV₀.
    4. Станция: `2A2A 06 xx 00` → общий ключ = ECDH(my_priv, peer_pub) (32 байта, AES-256).
    5. Дальше каждый кадр: `len u16 BE ‖ seed 4 байта ‖ AES-256-CBC(key, IV = MD5(seed), данные + нули до 16)`.
       Входящие уведомления могут приходить фрагментами — склеиваем до `6 + ceil(len/16)·16` байт.
  - Шифрование определяется автоматически: если за 3 с после подписки пришёл challenge `2A2A` — шифрованный
    режим, иначе открытый. Результат кешируется в состоянии.
- **Rationale**: протокол небольшой (≈400 строк), все примитивы есть в RustCrypto; без Python (принцип IV).
- **Alternatives**: вызывать `bluetti-read` из Python, как оригинал — нарушает принцип IV.
- **Риск**: проверить можно только на станции. Первая задача реализации — `bluetti-watcher read-once`
  с подробным логом кадров; владелец запускает её у станции.
- **Тесты**: CRC и кадры — на векторах из библиотеки; шифрование — круговой тест с фейковой «станцией»
  (сгенерированная пара K2/L1 в тестах подменяет константы через параметр).

## R2. Bluetooth LE на Windows

- **Decision**: WinRT напрямую через crate `windows` (`BluetoothLEDevice::FromBluetoothAddressAsync`,
  `GetGattServicesForUuidAsync`, `GattCharacteristic::ValueChanged`, `WriteValueWithResultAsync`).
- **Rationale**: подключение по адресу без предварительного сканирования, меньше прослоек, тот же crate нужен для
  схем питания, уведомлений и мьютекса.
- **Alternatives**: `btleplug` — на Windows требует сканирования перед подключением, хуже контроль над кешем GATT.
- **Правила**: подключение на каждый цикл и отключение после него (между циклами станция свободна для приложения
  BLUETTI на телефоне); таймаут цикла 30 с; `BluetoothCacheMode::Uncached` при повторе после ошибки.
- **Сканирование** (`bluetti-watcher scan`): `BluetoothLEAdvertisementWatcher` 10 с, имена `^AC180P\d+`
  и прочие BLUETTI.

## R3. Eco-режим

Проверено без прав администратора: `powercfg /duplicatescheme`, `/setacvalueindex` (PROCTHROTTLEMAX, VIDEOIDLE) и
`/delete` работают (exit 0). На ПК активна «Высокая производительность»; есть пользовательская схема
«Экономия (нет света)» `b1e771e0-ec00-4c0d-9a11-0000b10e771e` — её не трогаем.

- **Decision — своя схема питания**: при установке создаём схему «Bluetti Eco» копией «Экономии энергии»
  (`PowerDuplicateScheme`), GUID храним в состоянии. Eco = записать в неё PROCTHROTTLEMAX (80 % / глубокий 50 %),
  VIDEOIDLE 180 с и сделать активной (`PowerSetActiveScheme`). Снятие = вернуть сохранённую до eco активную схему.
  Через powrprof API из crate `windows`, без процессов.
- **Decision — GPU NVIDIA**: установка лимита мощности требует администратора. При установке (один элевированный
  шаг) регистрируется задача `BluettiWatcherGpu` с наивысшими правами, запускающая `bluetti-watcher.exe gpu-apply`.
  Сервис пишет желаемый уровень (`normal|eco|deep`) в `%ProgramData%\bluetti-watcher\gpu-request` и запускает задачу
  (`ITaskService`/`schtasks /run`). Элевированный процесс читает лимиты через NVML (`nvml-wrapper`) и ставит ватты,
  зажатые в `[min_limit, default_limit]` — подмена файла ничего опаснее «минимального лимита» сделать не может.
  RTX 3060 владельца: default 170 Вт, min 100 Вт, поэтому 50 % / 35 % от номинала упираются в 100 Вт. Расчёт:
  `max(min_limit, default × pct)`; eco по умолчанию 70 % (119 Вт), глубокий — `min_limit`.
- **Decision — энергосбережение Windows 11**: документированного API для режима «всегда включено» от сети нет.
  Используем оверлей «Наилучшая энергоэффективность» (`PowerSetActiveOverlayScheme`,
  `961cc777-2547-4f9d-8174-7d86181b8a7a`) — работает без прав, но только поверх «Сбалансированной», поэтому схема
  «Bluetti Eco» создаётся копией «Сбалансированной», если оверлей включён, иначе копией «Экономии энергии».
  Включение режима Energy Saver через реестр HKLM (неофициально, нужен админ) отвергнуто. Часть помечена как
  best effort: при ошибке остальные части eco применяются (FR-019b). Финальная проверка — задача-спайк в tasks.
- **Спайк T045 (2026-10-14)**: на ПК владельца без прав администратора (`cargo test -- --ignored overlay_spike`)
  `PowerDuplicateScheme` от «Сбалансированной», `PowerWriteFriendlyName`, `PowerSetActiveScheme` на копию и
  `PowerSetActiveOverlayScheme(961cc777-…)` (из powrprof.dll через `GetProcAddress`) — все код 0; чтение назад:
  активна копия, `PowerGetActualOverlayScheme` = `961cc777-…`. Возврат «Высокой производительности», оверлея
  `00000000-…` (исходный, без оверлея) и `PowerDeleteScheme` копии — код 0, итоговое состояние совпало с исходным.
  Влияние на потребление и частоты не замерялось. Решение подтверждено: оверлей — часть eco поверх «Bluetti Eco»
  (копия «Сбалансированной»), best effort.
- **Монитор**: VIDEOIDLE в схеме «Bluetti Eco», возвращается вместе со схемой.
- **Rationale**: всё обратимо одной операцией (вернуть прежнюю схему), пользовательские схемы не меняются.
- **Alternatives**: менять параметры активной схемы владельца и откатывать — сложнее и опаснее при сбое.

## R4. Гибернация

- **Факт**: на ПК владельца гибернация выключена (`powercfg /a`: «Режим гибернации не включен»).
- **Decision**: `SetSuspendState(hibernate=TRUE, force=FALSE, wakeup_events_disabled=FALSE)` из powrprof.
  Элевированный шаг установки выполняет `powercfg /h on`; сервис при старте проверяет доступность
  (`GetPwrCapabilities().HiberFilePresent`) и показывает на дашборде предупреждение, если гибернации нет.

## R5. Окно дашборда

- **Decision**: `bluetti-watcher.exe open` открывает окно через `wry` + `tao` (WebView2, есть в Windows 11:
  `Microsoft.Win32WebViewHost`, `EdgeWebView\Application`). Если сервис не отвечает — сначала запускает его.
- **Rationale**: своё окно с иконкой и заголовком, не зависит от Chrome/Edge и их профилей.
- **Alternatives**: `msedge --app=` как в оригинале — окно браузера, общий профиль, хуже группировка на панели.

## R6. Остальные решения

| Тема | Decision | Почему |
|---|---|---|
| Async | `tokio` (current_thread для сервиса) | WinRT-операции и HTTP в одном рантайме |
| HTTP | `axum`, SSE `/api/stream` для живых обновлений | небольшой, проверка `Host` middleware |
| БД | `rusqlite` (bundled), WAL | один файл, без внешнего SQLite |
| Конфиг | `config.toml` (`serde` + `toml`) | рядом с данными, комментарии допустимы |
| Лог | `tracing` + своя ротация по размеру (2 × 5 МБ) | FR-009 |
| Уведомления | `tauri-winrt-notification`, AUMID ярлыка в «Пуске» | toast без трея |
| Автозапуск | задача планировщика `BluettiWatcher` при входе, без элевации, перезапуск при сбое | как в оригинале, надёжнее ключа Run |
| Один экземпляр | именованный мьютекс `Local\BluettiWatcher` | FR-008 |
| Графики | uPlot (встроен в бинарник) | ~50 КБ, быстрый на 30 днях данных |
| Дизайн | макет в Claude Design после контрактов API | не блокирует ядро |
| Логика решений | порт правил из оригинала (`docs/design.md` §3, §5, §6, §7) без облака/ДТЭК/флага | правила уже отлажены |
